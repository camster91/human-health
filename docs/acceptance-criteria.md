# Product acceptance criteria baseline

Every user-facing feature should consider:

- Mobile-first use with representative tablet and desktop QA
- Keyboard and screen-reader basics
- Clear loading, empty, error, offline, stale-data, and sync-failure states
- No loss of active workout state on refresh or temporary connectivity loss where technically possible
- Explicit source/provenance for imported health data
- Explainable and reversible automatic coaching changes
- Historical workout data remains immutable
- Analytics events do not include sensitive health content unnecessarily
- Security and privacy review for sensitive data flows
- Deployment verification and documented rollback path
